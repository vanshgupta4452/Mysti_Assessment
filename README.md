## What this is

Daybreak Repairs (fictional) says it loses eight hours a week chasing customers and asks whether AI can fix it. This repository contains the research, the decision and a runnable dry-run prototype that tests the central technical claim.

- [`DECISION.md`](DECISION.md) — the decision note: user and problem, calculations, alternatives, the tested technical claim, recommendation, net value, next experiment.
- [`SOURCES.md`](SOURCES.md) — four external sources with URLs, access dates, the claim each supports, and labelled unverified assumptions.
- [`HANDOVER.md`](HANDOVER.md) — run commands, evidence index, limits, tool decisions.
- [`BRIEF.md`](BRIEF.md) — the supplied challenge brief, unmodified.

## Requirements

Python 3.10 or newer. **No third-party packages, no credentials, no network access.** Verified on Python 3.10.12 (Linux) and 3.11.15 (Windows 10). Nothing to install.

## Run it

All commands are run from this directory (`python3` on macOS/Linux, `py` on Windows).

```text
python -m unittest discover -s tests
python run.py
```

Expected:

```text
Ran 26 tests in 0.0Xs

OK
DRY RUN - nothing sent. data=.../track-b/data
requests=30 eligible=5 review=2 excluded=23 drafts=3
```

The test count, the `OK`, and the `requests=` line are the parts that matter; the elapsed time varies by machine.

`run.py` writes three files to `out/`:

| File | Contents |
| --- | --- |
| `out/report.md` | The evidence: logged effort, the eight-hour premise, the queue, the baseline comparison, the technical-claim check, net value |
| `out/decisions.csv` | All 30 requests with the reason for each outcome (eligible / review / excluded) |
| `out/proposed_actions.csv` | The unsent drafts, combined per case, with the reason and source IDs |

**Nothing is ever sent.** The prototype is a dry run: it generates drafts only. It imports no network or mail library, so a contact action is not possible.

## The two checks worth running

**1. Changed input — the 48-hour edge case.** Move the snapshot forward two hours so R016 and R029 land on *exactly* 48 hours. Predicted before running: eligible 5 → 7, drafts 3 → 5, pending-list rule breaks 10 → 8.

```text
python make_fixtures.py
python run.py --data fixtures/changed_48h --out out/changed_48h
```

Observed: `requests=30 eligible=7 review=2 excluded=21 drafts=5` — as predicted. This doubles as the "exactly 48 hours is eligible" edge case.

**2. No-action input.** A valid snapshot where nothing is eligible. The program must report this cleanly rather than fail.

```text
python run.py --data fixtures/no_action --out out/no_action
```

Observed: `requests=30 eligible=0 review=0 excluded=30 drafts=0` and `No follow-up proposed for this input.`

**3. Do the tests actually catch anything?** `mutation_check.py` breaks one rule at a time in a throwaway copy of the source, then re-runs the suite, and reports which tests noticed. All eight mutants are caught.

```text
python mutation_check.py
```

Expected: eight `M1 ... CAUGHT by <test names>` lines, then `all mutants caught`.

## Layout

```text
data/         the supplied evidence pack, unmodified (cases, events, requests, scenario)
followup.py   the rules engine: dedupe, effort audit, 48-hour clock, opt-outs, drafts, report
run.py        entry point -> out/
make_fixtures.py  builds the changed-input and no-action fixtures
mutation_check.py  breaks one rule at a time to prove the tests bite
tests/        26 tests, standard-library unittest
out/          generated evidence, committed so results can be read without running anything
fixtures/     generated changed-input cases, committed for the same reason
DATA_DICTIONARY.md, USER_NOTES.md, RESOURCE_STARTERS.md   supplied reference material
starter.py    the optional loader from the original pack, left as supplied
```

`out/` and `fixtures/` are committed on purpose so a reviewer can read the results without running anything. Both are regenerated byte-identically by the commands above.

## Reproducing from a clean clone

Delete `out/` and `fixtures/`, then run the commands in **Run it** and **The two checks worth running**. Every number quoted in `DECISION.md` and `HANDOVER.md` is reproduced, and is pinned by the test suite so a changed rule fails a test rather than silently altering a result.
